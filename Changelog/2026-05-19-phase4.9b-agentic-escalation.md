# 2026-05-19 Phase 4.9B Agentic Escalation

## Summary

本次变更完成了 Phase 4.9B：

- 默认 AIOps 巡检在发现异常后，不再只停留在“建议进入专项诊断”
- 系统会自动选择最高优先级异常，并升级进入对应专项 Profile
- 专项诊断明确采用“本地实时证据 -> 本地上下文 -> 本地 Runbook / RAG -> 外部补充参考”的优先级
- Tavily 外部搜索仅在本地知识不足或用户反馈已有建议无效时受控触发
- CPU / Memory / Disk 报告统一加入处置动作分级和危险操作边界

## Code Changes

- 重写 `host_health_engine.py`
  - 新增 `abnormal_findings`
  - 新增 escalation 目标选择
  - 新增 escalation payload
- 重写 `cpu_engine.py`
  - 本地实时证据优先
  - 本地 Runbook 优先
  - `web_search` 仅在本地知识不足或 remediation feedback failed 时触发
  - 报告新增“巡检升级说明 / 外部补充参考 / 处置动作分级”
- 重写 `memory_engine.py`
  - 行为与 CPU Runtime 保持一致
- 重写 `disk_engine.py`
  - 与 CPU / Memory 统一为同一套 4.9B 证据顺序和报告结构
- 扩展 `state.py`
  - `abnormal_findings`
  - `selected_escalation_profile`
  - `escalation_reason`
  - `host_health_evidence`
  - `remediation_feedback_failed`
- 修改 `aiops_service.py`
  - 识别“我按你说的做了还是没效果 / 继续查”等 remediation feedback failed 信号
- 修改 `replanner.py`
  - 在 host health patrol 收口前自动执行 runtime escalation
  - 记录 escalation trace 事件
