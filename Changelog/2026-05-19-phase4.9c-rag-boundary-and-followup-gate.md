# 2026-05-19 Phase 4.9C: RAG Boundary And Follow-up Gate

## Summary

- Added a RAG answer guard so ordinary knowledge chat no longer presents demo/mock knowledge as current realtime host facts.
- Added an AIOps follow-up context gate that classifies new questions as `independent`, `dependent_followup`, or `ambiguous`.
- Saved a compressed `PreviousAIOpsContext` for follow-up reasoning instead of replaying the full trace.
- Made Tavily external search model-gated rather than hardcoded to specific follow-up phrases.

## Key Changes

- Added `app/services/rag_answer_guard.py`.
- Wired the guard into `app/services/rag_agent_service.py` for both non-streaming and streaming ordinary RAG responses.
- Added `app/agent/aiops/followup_context.py` for:
  - previous AIOps context compaction
  - follow-up relation classification
  - follow-up context package construction
- Extended `PlanExecuteState` with:
  - `previous_aiops_context`
  - `followup_relation`
  - `followup_resolution`
- Updated `app/services/aiops_service.py` to:
  - persist compressed previous AIOps context
  - classify new turns before entering the graph
  - detect remediation-failure style user feedback
- Updated `app/agent/aiops/planner.py` so dependent follow-ups can choose between:
  - answering from previous context
  - rerunning the same profile
  - retrieving more local knowledge
  - using external search only when justified
  - asking for clarification
